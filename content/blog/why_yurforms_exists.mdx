Browser autofill is excellent at checkout pages. Those have `autocomplete="postal-code"` on the postal code field, because e-commerce had a commercial reason to standardise.

Everything else was built by someone who named the field `txtApplicantSurname_2` and never considered that a machine might read it. Job applications. Visa applications. University portals. Vendor onboarding. Insurance claims.

So the same twenty facts get typed by hand, again. And because they are typed rather than filled, they drift — the address on one application is one move out of date, the phone number on another still has the old country code. You do not notice, because you never see two of them side by side.

## Why name matching cannot fix this

Name-based matching is a lookup table. Lookup tables fail silently on inputs they have not seen.

Every unrecognised field name is a blank field and no signal that anything happened. The tool did not error. It just quietly did less than you thought, and you find out at the review step — or after submitting.

YurForms matches on **context** instead: the surrounding label text, the field type, its position in the form, the shape of the data expected. "Surname", "Family name" and "Last Name" all resolve to the same stored value regardless of what the `name` attribute says.

## The trade I did not expect to have to design around

Context matching generalises. That is the point.

Generalising means it can be **confidently wrong** — filling a plausible value into a field that meant something else entirely. A lookup table would have skipped that field. Mine fills it, convincingly, and you sign the form.

That is a strictly worse failure than a blank. A blank is visible.

So the architecture assumes the matcher will be wrong, rather than hoping it will not:

- **Conflict resolution** for when several stored values plausibly fit one field, instead of silently picking the first.
- **A feedback loop** — corrections are captured and improve subsequent matching, so a site that trips it up is fixed once, not every time.
- **Visible fill state in real time**, so you see what was filled *before* submitting.

That last one is the least clever feature and the one doing the most work. An automation that is occasionally wrong is fine when its output is inspectable. The same automation with invisible output is a liability.

## Two surfaces, because the browser makes you

A Next.js app is the vault and the management surface. A Chrome extension is where filling happens, because the extension is the only thing with access to the page.

Supabase for storage, auth and sync. SendGrid for transactional mail. Offline support in the extension so a flaky connection does not block a form, with reconciliation afterwards.

The split is not an architectural preference. It is the shape the platform imposes, and pretending otherwise leads to trying to do page manipulation from a web app, which does not work.

## The part I would not gloss over

Cross-device sync is the most-requested feature and the one that changes what this product *is*.

A local-only autofill tool holds data already on your machine. A syncing one holds a copy of your identity documents on a server I operate.

That is a different product with a different duty of care, and it is why secure storage and a privacy-first posture are stated as headline features rather than buried in an implementation section. For this category, the data-handling story is not a detail of the product — it is the product. A user who cannot answer "where does this live and who can read it" should not use it, and I would rather lose that user than obscure the answer.

The uncomfortable version: the feature that makes it useful is the feature that makes it dangerous. There is no design that removes that tension. There is only being straight about it.

## The measure

A tool that saves two minutes has to be pleasant enough that people reach for it rather than typing. Dark and light, responsive, minimalist, across both surfaces.

Two minutes is not much of a margin. Any friction in the tool itself eats the whole benefit.
