# GemChat: Containing AI Agents With Git Worktrees

## The Problem

The failure mode of an autonomous coding agent is not that it writes bad code. Bad code is reviewable. The failure mode is that it writes bad code *directly into your working tree*, across eleven files, interleaved with the three changes you had in progress — and by the time you notice, separating them is harder than redoing the work.

Every safety mechanism in GemChat descends from that observation. The question is not "how do we make the agent correct", it is "what does the agent get to touch before a human has looked".

## Architectural Deep-Dive

### Isolation as the default, not the option

Every orchestration run creates an isolated git worktree. Agents work there. The main branch is untouched until the human says otherwise. This is the load-bearing decision: it converts an unbounded risk (arbitrary edits to real work) into a bounded one (a directory you can delete), and it does so using a git primitive rather than a bespoke sandbox.

### Tiered approval

Tool calls are not equal. Reading a file is not deleting one; running a test is not running an arbitrary shell command. High-risk calls — shell execution, file deletion — stop and require explicit `y/n` confirmation in the TUI. Low-risk calls proceed.

The tiering is what makes the approval prompt meaningful. A system that confirms everything trains the user to press `y` without reading, which is strictly worse than no confirmation at all.

### Multi-agent decomposition

Complex goals are decomposed into sub-tasks handled by specialised agents — an Architect that plans, Coders that implement, Researchers that gather context. The value is not that more agents are smarter; it is that a decomposed run produces a legible pipeline. When the output is wrong, you can see *which stage* went wrong, instead of re-reading one long transcript.

### Persistence

Chat history, token usage and pipeline state are saved automatically and can be resumed. Token usage in particular is surfaced rather than hidden — an orchestration that fans out across agents can spend a great deal without any single step looking expensive, and a tool that hides that number is not being straight with its user.

### Provider portability

Built primarily for Google Gemini, with support for Anthropic Claude and OpenAI. The provider is configuration, not architecture — which matters because the model you should be using changes faster than the harness around it.

## Impact

Built with Rust and Ratatui, so the interface starts instantly, renders markdown and syntax highlighting inline, and stays responsive while requests stream. It is a coding assistant that behaves like a terminal tool rather than a web app pretending to be one.
